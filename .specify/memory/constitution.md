# 個人旅行工具 Constitution

## Core Principles

### I. 三階段旅行流程
本工具 MUST 支援行前規劃、旅途中使用與旅後回顧三個階段。行前規劃 MUST 以電腦大螢幕及鍵盤滑鼠操作為優先，方便大量編輯行程。旅途中 MUST 能在手機查看已輸出的行程並記錄花費；手機上的行程內容以唯讀為主。旅後 MUST 能將手機記錄的花費匯入電腦，並在電腦端查看完整花費結果。各階段的功能與驗收結果 MUST 清楚對應其使用情境。

### II. 旅途離線使用
手機端 MUST 在沒有網路連線時提供已輸出的行程查看與花費記錄功能。行程及花費記錄 MUST 儲存在手機本機，旅途中的新增、查看與保存 MUST 不依賴網路或遠端服務。輸出至手機的內容 MUST 包含離線查看所需資料；離線記錄的花費 MUST 在匯出前保留於手機。

### III. 裝置獨立與使用者掌控資料
工具 MUST 不要求帳號登入，並將資料儲存在使用者控制的裝置上。電腦與手機在旅途中 MUST 各自獨立運作，不要求即時或背景同步。行程輸出至手機，以及花費記錄由手機匯出並在電腦匯入，MUST 由使用者明確發起；花費以旅程結束後一次匯出為原則。資料交換 MUST 不以遠端服務作為必要條件。

### IV. 功能必須有測試
每項功能及使用者可觀察的行為變更 MUST 至少有一項自動化測試，對應明確的預期結果。測試 MUST 涵蓋行程規劃與輸出、手機離線查看、離線新增及保存花費、花費匯出與電腦匯入，以及電腦端完整花費結果。跨裝置資料交換 MUST 以整合測試驗證；修正缺陷 MUST 加入可重現該缺陷的回歸測試。合併前 MUST 執行相關測試並確認通過。

### V. 簡單且聚焦
功能 MUST 直接支援行前規劃、旅途中查看或記帳、旅後花費回顧的具體需求。沒有明確使用情境與驗收條件的功能 MUST 暫緩；能以較簡單方案滿足需求時 MUST 優先採用較簡單方案。不得為假設性需求增加不必要的設定、帳號、同步機制或服務依賴。

### VI. 全站視覺一致
所有面向使用者的頁面與元件 MUST 遵循 [docs/design-guide.md](../../docs/design-guide.md) 所定義的日本生活風格雜誌編輯美學，並在全站一致套用其配色、字體、留白、分隔、元件、地圖、響應式版面與深色模式規範。視覺風格 MUST 不犧牲指南訂定的可讀性底線，包括 WCAG AA 對比度、手機內文至少 16px，以及手機按鈕高度至少 44px。若具體需求必須偏離指南，變更 MUST 先記錄於設計指南並說明理由，且驗證其可讀性與全站一致性。

## Additional Constraints

所有面向使用者的介面文字、提示與錯誤訊息 MUST 使用繁體中文。手機介面 MUST 適合單手操作、文字清楚，且開啟後立即呈現行程或記帳情境的重點。輸出至手機的行程 MUST 清楚呈現，並將離線查看所需內容一併提供。手機匯出的花費資料 MUST 可由電腦匯入，以供旅後查看完整花費結果。

## Development Workflow

每項需求 MUST 說明對應的使用階段與可驗收結果。驗證 MUST 涵蓋受影響的使用情境；涉及手機輸出、離線資料保存、花費匯出或匯入時，測試 MUST 覆蓋完整受影響流程，並確認沒有網路時仍可完成旅途中必要操作。審查變更時 MUST 確認其符合本憲章，且新增複雜度有具體需求支持。
