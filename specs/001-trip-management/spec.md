# Feature Specification: 建立與管理旅程（電腦端）

**Feature Branch**: `001-trip-management`

**Created**: 2026-10-16

**Status**: Draft

**Input**: User description: 建立電腦端旅程管理功能，讓個人旅行者設定旅程基本資訊、瀏覽與分類旅程列表、編輯、刪除及複製旅程，並確保資料重新開啟瀏覽器後仍存在。每日行程、地圖、交通、手機輸出、花費記錄與統計、多人共同編輯不在本次範圍。

## Clarifications

### Session 2026-10-16

- Q: 進行中的旅程要如何分類？ → A: 新增「旅途中」分類；出發日當天至回程日當天（含）均歸入此類。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建立並保存旅程 (Priority: P1)

使用者在電腦上建立一趟旅程，輸入名稱、目的地、出發與回程日期，可選擇填寫預算、同行者及備註，儲存後能在旅程列表找到該旅程。

**Why this priority**: 旅程是後續規劃與記錄的基本容器；若無法建立並保存，其他管理操作都無從開始。

**Independent Test**: 建立一趟包含必填資料的旅程，確認旅程出現在首頁；關閉並重新開啟瀏覽器後，確認資料仍存在。

**Acceptance Scenarios**:

1. **Given** 使用者位於尚無旅程的首頁，**When** 選擇「建立第一趟旅程」、填寫有效的必填資料並儲存，**Then** 系統建立旅程並在首頁列表顯示名稱、目的地、日期及天數。
2. **Given** 使用者建立旅程，**When** 填寫多個目的地、多人同行者及選填備註後儲存，**Then** 所有輸入內容都保存在該旅程中。
3. **Given** 使用者已儲存旅程，**When** 關閉瀏覽器並重新開啟同一工具，**Then** 旅程仍可在首頁查看。
4. **Given** 使用者未填旅程名稱、目的地、出發日期或回程日期其中之一，**When** 嘗試儲存，**Then** 系統指出缺少的必填欄位且不建立旅程。
5. **Given** 使用者輸入早於出發日期的回程日期，**When** 嘗試儲存，**Then** 系統顯示清楚的日期錯誤提示且不建立旅程。
6. **Given** 使用者填寫預算金額，**When** 金額為零或負數，**Then** 系統顯示清楚的預算錯誤提示且不建立旅程。
7. **Given** 使用者操作旅程建立介面或收到欄位驗證提示，**When** 查看介面文字與提示，**Then** 內容皆使用繁體中文。

---

### User Story 2 - 瀏覽及辨識旅程 (Priority: P2)

使用者在首頁查看所有旅程，依出發日期排序，辨認即將出發、旅途中與已結束的旅程，並能快速查看每趟旅程的目的地、日期與天數。第一次使用且尚無旅程時，首頁提供建立入口。

**Why this priority**: 列表是使用者找到並進入旅程的主要入口，也能在旅程數量增加後協助快速辨識。

**Independent Test**: 建立出發日期不同且狀態不同的多趟旅程，檢查列表資訊、排序及分類；另以空資料狀態確認引導內容與建立按鈕。

**Acceptance Scenarios**:

1. **Given** 使用者尚未建立任何旅程，**When** 開啟首頁，**Then** 系統顯示引導文字及「建立第一趟旅程」按鈕。
2. **Given** 使用者有多趟不同日期的旅程，**When** 查看首頁，**Then** 每趟旅程都顯示名稱、目的地、出發日期、回程日期及天數，並依出發日期由早至晚排序。
3. **Given** 旅程的出發日與回程日相同，**When** 查看列表，**Then** 系統顯示旅程為 1 天。
4. **Given** 使用者有尚未出發、旅途中及已結束的旅程，**When** 查看首頁，**Then** 系統分別將旅程列於「即將出發」、「旅途中」及「已結束」。
5. **Given** 今天是旅程的出發日、回程日，或兩日期之間的任一天，**When** 查看首頁，**Then** 該旅程列於「旅途中」。

---

### User Story 3 - 編輯、刪除及複製旅程 (Priority: P3)

使用者開啟一趟旅程後檢視或修改基本資訊；不再需要的旅程可經再次確認後刪除；也可複製舊旅程資料作為新旅程起點，且新舊旅程可分別編輯。

**Why this priority**: 旅程日期或內容可能改變，且重複使用既有資料能減少建立相似旅程的輸入工作。

**Independent Test**: 開啟旅程並修改資料後重新查看；分別測試刪除確認與取消；複製旅程並驗證新舊資料互不覆寫。

**Acceptance Scenarios**:

1. **Given** 使用者從列表開啟一趟旅程，**When** 修改基本資訊並儲存，**Then** 系統保存修改，且列表更新受影響的資訊與天數。
2. **Given** 使用者選擇刪除一趟旅程，**When** 系統要求再次確認且使用者確認，**Then** 該旅程從列表移除。
3. **Given** 使用者選擇刪除一趟旅程，**When** 系統要求再次確認且使用者取消，**Then** 該旅程仍保留且內容不變。
4. **Given** 使用者選擇複製一趟舊旅程，**When** 系統建立可編輯的新旅程起點並由使用者儲存，**Then** 新旅程沿用來源旅程的基本資訊，且與來源旅程分開保存。
5. **Given** 使用者已複製一趟旅程，**When** 修改新旅程的任一基本資訊，**Then** 來源旅程的資訊不受影響。

### Edge Cases

- 出發日期與回程日期相同時，旅程天數為 1 天；回程日期早於出發日期時，阻止儲存並說明錯誤。
- 名稱或目的地只包含空白時，視為未填必填資料並指出欄位。
- 預算未填時可正常儲存；填寫預算金額時，金額必須大於零且必須同時選擇幣別。
- 目的地或同行者包含多個項目時，列表與旅程檢視不得將項目合併成無法辨識的單一內容。
- 刪除確認尚未完成時不得移除旅程；取消確認後資料保持不變。
- 旅程複製後修改或刪除其中一趟，不得改動另一趟。
- 出發日當天至回程日當天（含）歸入「旅途中」；出發日在今天之後歸入「即將出發」；回程日在今天之前歸入「已結束」。
- 同一出發日期有多趟旅程時，列表仍須穩定顯示全部旅程；同日內次排序方式未指定。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 讓使用者在電腦端建立旅程，並輸入旅程名稱、至少一個目的地、出發日期及回程日期。
- **FR-002**: 系統 MUST 允許使用者選填總預算金額與幣別、零位或多位同行者名稱，以及備註。
- **FR-003**: 系統 MUST 阻止缺少旅程名稱、目的地、出發日期或回程日期的旅程儲存，並指出缺漏欄位。
- **FR-004**: 系統 MUST 阻止回程日期早於出發日期的旅程儲存，並顯示清楚的繁體中文提示。
- **FR-005**: 系統 MUST 在預算金額有填寫時，要求金額大於零且幣別有填寫；未填預算時允許旅程儲存。
- **FR-006**: 系統 MUST 依出發日期與回程日期計算旅程天數，且首尾日期都計入天數。
- **FR-007**: 系統 MUST 在首頁列出所有已保存旅程，顯示名稱、目的地、出發日期、回程日期及天數，並依出發日期由早至晚排序。
- **FR-008**: 系統 MUST 依使用者電腦的當地日期將旅程分為「即將出發」、「旅途中」與「已結束」：出發日在今天之後為「即將出發」；今天介於出發日與回程日之間且包含首尾日期為「旅途中」；回程日在今天之前為「已結束」。
- **FR-009**: 系統 MUST 在沒有任何旅程時，於首頁顯示引導文字及「建立第一趟旅程」按鈕。
- **FR-010**: 系統 MUST 讓使用者開啟、檢視並編輯旅程基本資訊；儲存修改後，旅程詳情及列表衍生資訊須一致更新。
- **FR-011**: 系統 MUST 在刪除旅程前要求使用者再次確認；使用者取消時不得刪除。
- **FR-012**: 系統 MUST 讓使用者複製既有旅程作為新旅程起點；新旅程在使用者儲存後獨立存在，修改或刪除任一旅程不得改動另一趟。
- **FR-013**: 系統 MUST 將旅程資料保存在使用者裝置上，並在關閉及重新開啟同一瀏覽器後保留資料。
- **FR-014**: 所有介面文字與驗證提示 MUST 使用繁體中文。
- **FR-015**: 本規格定義的每一項使用者可觀察功能 MUST 至少有一項自動化測試對應其驗收結果。

### Key Entities *(include if data involved)*

- **旅程**：使用者建立與管理的旅行單位，包含名稱、目的地清單、出發日期、回程日期、可選的預算金額與幣別、同行者清單及備註；天數由日期計算得出。
- **目的地**：旅程包含的一個地區名稱；一趟旅程可包含多個目的地。
- **同行者**：旅程中可選填的一位同行者名稱；一趟旅程可包含多人。
- **預算**：旅程可選填的總預算金額與幣別；有金額時須同時有幣別，且金額必須大於零。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者能在單一建立流程中填妥必填資料並保存旅程，且首頁立即可找到該旅程。
- **SC-002**: 對於任何已保存旅程，關閉並重新開啟同一瀏覽器後，使用者仍可查看其已保存基本資訊。
- **SC-003**: 對任意有效日期組合，首頁呈現的旅程天數等於出發日與回程日之間的日曆天數且首尾皆計入；所有旅程依出發日期排序，並依當地日期正確列入「即將出發」、「旅途中」或「已結束」。
- **SC-004**: 缺少任一必填欄位、回程早於出發日，或預算金額小於等於零時，系統均阻止儲存並提供可辨識的錯誤提示。
- **SC-005**: 首頁無旅程時提供建立入口；刪除需二次確認；複製所得旅程可獨立修改，以上行為皆符合各自驗收情境。

## Assumptions

- 旅程天數以日曆日計算，出發日與回程日都計入；同日往返為 1 天。
- 日期分類以使用者電腦的當地日期為準；出發日及回程日當天均視為「旅途中」。
- 提供預算金額時，使用者也必須提供幣別；本功能至少支援使用者情境中明確提及的新台幣與日圓。
- 複製旅程會先以來源旅程基本資訊預填一筆新的可編輯旅程，使用者可調整資料後再保存；複製不會覆寫來源。
- 資料保存在建立旅程的使用者裝置，持續性以同一工具及同一瀏覽器重新開啟為驗收情境；登入、多裝置同步與資料匯出不屬本功能。
- 每個旅程名稱不要求全域唯一；同一出發日的旅程維持完整顯示，次排序方式由產品實作決定。
- 不在本次範圍：每日行程、地圖、交通方式、手機輸出、花費記錄與預算統計、多人共同編輯。
