# Quickstart: 每日行程、交通方式與地圖 驗證指南

**Feature**: [spec.md](./spec.md) | **Data model**: [data-model.md](./data-model.md) | **Contracts**: [google-maps-urls.md](./contracts/google-maps-urls.md)、[location-input.md](./contracts/location-input.md)

## 前置條件

- Node.js 24 以上，已執行 `npm install`（含 `leaflet`、`react-leaflet`、`@types/leaflet`）。
- 已完成功能 001，瀏覽器中至少有一趟旅程；建議使用 12.10–12.18 共 9 天、目的地為岡山、香川、愛媛的旅程。
- 真實瀏覽器檢查需要網路連線以載入 CARTO 圖磚。

## 自動化驗證

```bash
npx vitest run     # 單元＋整合測試全部通過
npm run typecheck  # 無型別錯誤
npm run build      # production build 成功
```

應包含的測試範圍（細節見 tasks.md）：座標／網址解析的全部合約案例、Google 地圖連結的全部合約案例、旅程日列表、排序與失效交通段計算、地圖模型、Dexie version 1 → 2 升級保留旅程、刪除旅程連帶刪除每日行程、旅程縮短的警告流程。

## 手動驗證（`npm run dev`，電腦寬度 ≥ 1280px）

1. **旅程日**：開啟旅程 → 每日行程，確認列出 Day 1・12.10 THU 至 Day 9・12.18 FRI，可切換。
2. **新增地點（三種方式）**，在 Day 1：
   - 貼上 `34.6672, 133.9354`，名稱「岡山後樂園」，抵達 09:00。
   - 從電腦版 Google 地圖複製「岡山城」的網址貼上，確認自動帶入名稱與座標，抵達 11:30。
   - 手動輸入「倉敷美觀地區」（不填座標），抵達 14:00。
   - 確認時間軸順序為後樂園 → 岡山城 → 倉敷，倉敷不在地圖上。
3. **無法辨識的輸入**：貼上 `https://maps.app.goo.gl/xxxx`，確認顯示短網址提示且無法以此座標儲存。
4. **交通方式**：後樂園 → 岡山城設為步行、岡山城 → 倉敷設為 JR／電車；確認地圖上第一段為圓點線，未設定的段落顯示「未設定」；圖例說明各線條樣式。
5. **Google 地圖連結**：點兩段的「在 Google 地圖開啟」，確認新分頁開啟、起訖正確；第一段為步行模式，第二段（倉敷無座標）以名稱查詢、大眾運輸模式。
6. **重新排序**：把岡山城的抵達時間改為 08:30，確認清單、地圖編號與連線立即更新；相鄰關係改變的段落變為「未設定」。
7. **地圖與清單互相對應**：點地圖上的 2 號標記，清單對應項目強調並捲入畫面；點清單項目，地圖標記強調並移入可見範圍。
8. **移到另一天與刪除**：把一個地點移到 Day 3、刪除一個地點（先取消再確認），確認兩天的時間軸與交通段正確。
9. **空白日**：切換到沒有地點的 Day 5，確認顯示引導文字與「新增地點」按鈕，地圖顯示整趟旅程地點的範圍；在一趟完全沒有座標的新旅程中，地圖顯示亞洲範圍。
10. **旅程日期變更**：
    - 在 Day 9 加入地點，將旅程整體平移為 12.11–12.19 → 不警告，地點仍在 Day 9（日期顯示 12.19）。
    - 將回程日期提前一天 → 出現警告，列出受影響天數與地點數；分別測試「取消」（日期不變）、「移到 Day 2」、「刪除這些地點」。
11. **持久性**：關閉瀏覽器再開啟，所有地點、時間與交通方式仍存在。
12. **既有資料**：使用 001 時期建立的舊旅程（升級前的資料庫）開啟本版本，旅程資料完整、每日行程為空。
13. **視覺**（對照 `docs/design-guide.md`）：左側時間軸、右側地圖雙欄；灰階 Positron 底圖、深色模式改為 Dark Matter；標記為墨黑圓形編號、選取時點綴色，無藍色圖釘或破圖；右下角顯示 © OpenStreetMap contributors © CARTO。
14. **地圖無法載入**：在 DevTools 將網路設為 Offline 後重新整理每日行程，確認顯示「地圖暫時無法載入」，時間軸、交通方式與連結仍可使用。
